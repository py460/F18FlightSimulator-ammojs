## 知识点 1：import / export 模块系统

### 是什么

TypeScript（和现代 JS）用 `import/export` 把代码拆成独立文件，每个文件是一个「模块」，只暴露自己想暴露的东西。

### 最小示例

```typescript
// math.ts —— 定义并导出
export function add(a: number, b: number): number {
    return a + b;
}
export const PI = 3.14159;

// main.ts —— 导入并使用
import { add, PI } from './math';
console.log(add(1, 2));  // 3
console.log(PI);          // 3.14159
```

### 在 F18 项目中的真实用法

```typescript
// 来源：src/game.ts 第 1-9 行
import { F18GamepadController } from './vehicleObject/f18/f18GamePadController';
import * as BABYLON from '@babylonjs/core'
import { AmmoJSPlugin } from '@babylonjs/core';
import { F18Assets } from './vehicleObject/f18/f18Assets';
import { F18Physics } from './vehicleObject/f18/f18Physics';
import { AirportScene } from './physicsScene/airportScene';
import { F18CameraController } from './vehicleObject/f18/f18CameraController';
import { F18InputController } from './vehicleObject/f18/f18InputController';
```

- `import { F18Physics } from './...'`：按名字导入，花括号里的名字必须和导出时一致
- `import * as BABYLON from '@babylonjs/core'`：把整个包的所有导出挂到 `BABYLON` 命名空间下，之后用 `BABYLON.Scene`、`BABYLON.Mesh` 等访问
- `'@babylonjs/core'` 是 npm 包名（不是相对路径），`'./vehicleObject/...'` 是相对路径（必须以 `./` 或 `../` 开头）

### 为什么这样写

如果没有模块系统，所有代码都在一个文件里，1000 行以上就无法维护。模块让每个文件只关心自己的职责，`F18Physics` 不需要知道 `AirportScene` 的实现细节。

### 常见错误

```typescript
// ❌ 错误：忘记花括号（这是导入默认导出，不是命名导出）
import F18Physics from './f18Physics';

// ✅ 正确：命名导出用花括号
import { F18Physics } from './f18Physics';

// ❌ 错误：路径写错（少了 ./ 前缀）
import { F18Physics } from 'f18Physics';  // 会被当成 npm 包名
```

## 知识点 2：class 类定义

### 是什么

`class` 是创建对象的模板，把数据（属性）和行为（方法）封装在一起。TypeScript 的 class 比 Java/C++ 的 class 更灵活，比 Python 的 class 更严格。

### 最小示例

```typescript
class Dog {
    name: string;       // 属性声明（TypeScript 必须先声明）
    age: number;

    constructor(name: string, age: number) {  // 构造函数
        this.name = name;
        this.age = age;
    }

    bark(): void {      // 方法，void 表示无返回值
        console.log(`${this.name} says: Woof!`);
    }
}

const dog = new Dog('Rex', 3);
dog.bark();  // Rex says: Woof!
```

### 在 F18 项目中的真实用法

```typescript
// 来源：src/game.ts
export class Game {
    // 属性声明（TypeScript 要求在 class 顶部声明所有属性）
    private _canvas: HTMLCanvasElement;
    private _engine: any;
    private scene: BABYLON.Scene;
    private flyList = [];       // 直接赋初始值也可以
    private flyMesh;
    private airportScene: AirportScene;

    // 构造函数：new Game('renderCanvas') 时执行
    constructor(canvasElement: string) {
        // document.getElementById 返回 Element | null
        // <HTMLCanvasElement> 是类型断言，告诉 TS "我确定它是 canvas"
        this._canvas = <HTMLCanvasElement>document.getElementById(canvasElement);
        this._engine = new BABYLON.Engine(this._canvas, true);
    }

    // 异步方法（返回 Promise，可以用 await 等待）
    async createScene() {
        this.scene = new BABYLON.Scene(this._engine);
        // ...
    }
}
```

### 为什么这样写

`Game` 类把引擎、场景、飞机列表都封装在一起，外部只需要 `new Game('renderCanvas')` 然后调 `createScene()`，不需要关心内部细节。

### 常见错误

```typescript
// ❌ 错误：TypeScript 中属性必须先声明，不能直接在构造函数里赋值
class Bad {
    constructor() {
        this.name = 'test';  // 报错：Property 'name' does not exist
    }
}

// ✅ 正确：先声明
class Good {
    name: string;
    constructor() {
        this.name = 'test';
    }
}

// ✅ 也可以用构造函数参数简写（等价于上面）
class Better {
    constructor(public name: string) {}
}
```

## 知识点 3：public / private 访问修饰符

### 是什么

控制属性和方法能否从类外部访问：
- `public`：任何地方都能访问（默认值，不写也是 public）
- `private`：只有类内部能访问
- `protected`：类内部 + 子类能访问（本项目未使用）

### 在 F18 项目中的真实用法

```typescript
// 来源：src/vehicleObject/f18/f18Physics.ts
export class F18Physics {

    // public：外部可以读写，其他模块需要访问这些数据
    public vehicle: Ammo.btRaycastVehicle      // 物理载具对象
    public chassisMesh: BABYLON.Mesh           // 机身网格（相机需要跟随它）
    public wheelMeshes = [];                   // 轮胎网格数组
    public flyGamePadData = { ... }            // 输入控制器需要写入这里
    public flyData: FlyData = { ... }          // HUD 需要读取这里
    public showHud = false;                    // 相机控制器需要设置这个

    // private：内部实现细节，外部不应该直接操作
    private vehicleBody: Ammo.btRigidBody      // 刚体（外部不需要直接操作）
    private vehicleReady = false;              // 内部状态标志
    private chassisWidth = 2;                  // 物理参数（外部不需要改）
    private scene: BABYLON.Scene;             // 场景引用（内部使用）

    // private 方法：内部实现，外部不调用
    private createVehicle() { ... }
    private addCompound(size, position, quaternion) { ... }

    // public 方法：对外接口
    public init(position, quaternion) { ... }
    public dispose() { ... }
    public explode() { ... }
}
```

### 为什么这样写

`chassisMesh` 是 public 因为 `F18CameraController` 需要把相机 parent 到它上面；`vehicleBody` 是 private 因为只有 `F18Physics` 内部的物理计算才需要直接操作刚体，外部不应该绕过飞控逻辑直接改刚体状态。

### 常见错误

```typescript
const fly = new F18Physics(canvas, engine, scene, flyMesh);

// ❌ 运行时不报错，但 TypeScript 编译时报错
fly.vehicleBody.setLinearVelocity(...);  // 'vehicleBody' is private

// ✅ 通过公开方法操作
fly.init(position, quaternion);
fly.dispose();
```

## 知识点 4：箭头函数与普通函数的 this 差异

### 是什么

TypeScript/JS 中有两种函数写法，关键区别在于 `this` 的绑定：
- 普通函数 `function() {}`：`this` 由调用方式决定（容易出错）
- 箭头函数 `() => {}`：`this` 永远指向定义时的外层对象（更安全）

### 在 F18 项目中的真实用法

```typescript
// 来源：src/vehicleObject/f18/f18Physics.ts createVehicle 方法内
// 箭头函数作为局部函数，this 指向 F18Physics 实例
let addWheel = (isFront, pos, radius, width, index) => {
    let wheelInfo = this.vehicle.addWheel(  // this 正确指向 F18Physics
        pos,
        this.wheelDirectionCS0,             // 可以访问实例属性
        this.wheelAxleCS,
        this.suspensionRestLength,
        radius,
        tuning,
        isFront
    );
    this.wheelMeshes[index] = this.createWheelMesh(radius, width);
}

// 调用
addWheel(true, new Ammo.btVector3(...), this.wheelRadiusFront, ...);
```

```typescript
// 来源：src/vehicleObject/f18/f18CameraController.ts
// 事件回调必须用箭头函数，否则 this 会丢失
private addEvent() {
    // ✅ 箭头函数：this 指向 F18CameraController 实例
    document.addEventListener('pointerlockchange', this._pointerlockchange = () => {
        if (document.pointerLockElement == this.canvas) {  // this 正确
            document.getElementById("input_panel").style.display = "none"
        }
    }, false);
}
```

### 常见错误

```typescript
// ❌ 普通函数作为事件回调，this 会变成 undefined 或 window
document.addEventListener('click', function() {
    this.canvas.requestPointerLock();  // this 不是 F18CameraController！
});

// ✅ 箭头函数保持 this
document.addEventListener('click', () => {
    this.canvas.requestPointerLock();  // this 正确
});
```

## 小结

| 知识点 | 核心记忆 | 项目中的典型位置 |
|--------|---------|----------------|
