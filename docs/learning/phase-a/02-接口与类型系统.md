## 知识点 1：interface 接口

### 是什么

`interface` 定义一个「数据形状」——规定一个对象必须有哪些属性、各是什么类型。它只存在于编译阶段，运行时不产生任何代码。

### 最小示例

```typescript
// 定义接口
interface Point {
    x: number;
    y: number;
    label?: string;  // ? 表示可选属性
}

// 使用接口
function printPoint(p: Point): void {
    console.log(`(${p.x}, ${p.y})`);
    if (p.label) {
        console.log(p.label);
    }
}

printPoint({ x: 1, y: 2 });              // ✅
printPoint({ x: 1, y: 2, label: 'A' }); // ✅
printPoint({ x: 1 });                    // ❌ 编译错误：缺少 y
```

### 在 F18 项目中的真实用法

```typescript
// 来源：src/interface/fly.ts
// 注意：这个文件没有 export！这是「全局声明」（见知识点 2）

interface FlyData {
    accelerateSize,   // 油门大小（0~1000）
    resistance,       // 空气阻力系数
    flySpeed,         // 飞行速度 km/h
    flyLift           // 升力 N
}

interface FlyInputData {
    pitchUp: boolean;    // 俯仰抬头
    pitchDown: boolean;  // 俯仰低头
    rollLeft: boolean;   // 翻滚左
    rollRight: boolean;  // 翻滚右
    yawLeft: boolean;    // 偏航左
    yawRight: boolean;   // 偏航右
    accelerate: boolean; // 加速
    brake: boolean;      // 刹车
}
```

这两个接口被 `F18Physics` 和 `F18InputController` 使用：

```typescript
// 来源：src/vehicleObject/f18/f18Physics.ts
public flyData: FlyData = {
    accelerateSize: 0,
    resistance: 0.1,
    flySpeed: 0,
    flyLift: 0
}

// 来源：src/vehicleObject/f18/f18InputController.ts
public flyInputData: FlyInputData = {
    pitchUp: false,
    pitchDown: false,
    rollLeft: false,
    rollRight: false,
    yawLeft: false,
    yawRight: false,
    accelerate: false,
    brake: false
}
```

### 为什么这样写

如果没有接口，`flyData` 就是一个普通对象 `{}`，TypeScript 不知道它有哪些属性，写 `flyData.flySpedd`（拼写错误）也不会报错。有了接口，拼写错误会在编译时立刻被发现。

## 知识点 2：全局声明（无 export 的 interface）

### 是什么

TypeScript 中，如果一个文件**没有任何 `import` 或 `export`**，它就是「脚本模式」，里面定义的 `interface` 会自动成为全局类型，整个项目都能用，不需要 import。

### 在 F18 项目中的真实用法

```typescript
// 来源：src/interface/fly.ts
// 这个文件没有 import，没有 export
// 所以 FlyData 和 FlyInputData 是全局类型

interface FlyData { ... }
interface FlyInputData { ... }
```

```typescript
// 来源：src/vehicleObject/f18/f18Physics.ts
// 直接使用 FlyData，不需要 import！
public flyData: FlyData = { ... }
```

### 为什么这样写

对于整个项目都要用的「领域模型」类型（飞机数据、输入数据），放在全局声明里最方便，不用每个文件都 import。

> ⚠️ 注意：这种方式在大型项目中不推荐（容易命名冲突），但对小项目很实用。

## 知识点 3：类型断言 as / `<Type>`

### 是什么

当 TypeScript 推断出的类型比你知道的「更宽泛」时，用类型断言告诉编译器「我确定它是这个类型」。

### 最小示例

```typescript
// document.getElementById 返回 HTMLElement | null（宽泛类型）
const el = document.getElementById('myCanvas');
// el.width  // ❌ 报错：HTMLElement 没有 width 属性

// 类型断言：我确定它是 HTMLCanvasElement
const canvas = document.getElementById('myCanvas') as HTMLCanvasElement;
canvas.width;  // ✅ HTMLCanvasElement 有 width

// 另一种写法（效果相同，但在 JSX 中不能用）
const canvas2 = <HTMLCanvasElement>document.getElementById('myCanvas');
```

### 在 F18 项目中的真实用法

```typescript
// 来源：src/game.ts 构造函数
constructor(canvasElement: string) {
    // getElementById 返回 Element | null
    // 用 <HTMLCanvasElement> 断言为具体类型
    this._canvas = <HTMLCanvasElement>document.getElementById(canvasElement);
    this._engine = new BABYLON.Engine(this._canvas, true);
}
```

```typescript
// 来源：src/vehicleObject/f18/f18Physics.ts render 方法
// fpsDt 实际是 number，但 getAnimationRatio() 返回类型可能不精确
let fpsDt: any = this.scene.getAnimationRatio()
// 用 any 绕过类型检查（这是一种妥协，不推荐滥用）
```

### 常见错误

```typescript
// ❌ 不能断言成完全不相关的类型
const num = 42 as string;  // 报错：number 和 string 没有重叠

// ✅ 可以先断言成 unknown 再断言成目标类型（双重断言，谨慎使用）
const num = 42 as unknown as string;  // 编译通过，但运行时可能出错
```

## 知识点 4：联合类型与字面量类型

### 是什么

- **联合类型** `A | B`：值可以是 A 类型或 B 类型
- **字面量类型**：值只能是特定的字符串/数字

### 在 F18 项目中的真实用法

```typescript
// 来源：src/vehicleObject/f18/f18CameraController.ts
// flyViews 是字符串数组，每个元素只能是这三个值之一
public flyViews = ["tps", "fps", "target"]
public flyViewIndex = 0

// 使用时通过索引访问
if (this.flyViews[this.flyViewIndex] == "fps") {
    this.vehicle.showHud = true;
}
```

如果用更严格的 TypeScript 写法，可以这样定义：

```typescript
// 更严格的写法（项目中未使用，但这是最佳实践）
type CameraView = "tps" | "fps" | "target";
public flyViews: CameraView[] = ["tps", "fps", "target"];
```

## 知识点 5：`any` 类型

### 是什么

`any` 是 TypeScript 的「逃生舱」，告诉编译器「不要检查这个变量的类型」。用了 `any` 就失去了类型安全。

### 在 F18 项目中的真实用法

```typescript
// 来源：src/game.ts
private _engine: any;  // 应该是 BABYLON.Engine，但用 any 避免了复杂的类型导入

// 来源：src/vehicleObject/f18/f18Physics.ts
let fpsDt: any = this.scene.getAnimationRatio()
// getAnimationRatio() 实际返回 number，用 any 是为了避免某些运算的类型报错
```

> ⚠️ 本项目 `tsconfig.json` 设置了 `"noImplicitAny": false`，意味着即使不写类型也不报错。这降低了类型安全性，是快速开发的取舍。

### 什么时候用 any

- 接入没有类型定义的第三方库（如 Ammo.js 的部分 API）
- 快速原型开发，后续再补类型
- 永远不要在生产代码的核心逻辑里用 `any`

## 小结

| 知识点 | 核心记忆 | 项目中的典型位置 |
|--------|---------|----------------|
| `interface` | 定义数据形状，编译时检查 | `interface/fly.ts` |
