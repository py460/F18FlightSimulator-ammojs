## 知识点 1：为什么需要异步

### 问题背景

浏览器是单线程的。如果加载一个 50MB 的 3D 模型用「同步」方式（等加载完再继续），整个页面会卡死。异步让你「发出请求后继续做别的事，等结果回来再处理」。

### 三种异步写法的演进

```typescript
// 方式 1：回调函数（最老，容易嵌套地狱）
loadModel('f18.glb', function(model) {
    loadMap('map.glb', function(map) {
        loadSound('engine.mp3', function(sound) {
            // 三层嵌套，难以维护
        });
    });
});

// 方式 2：Promise 链（改善了嵌套）
loadModel('f18.glb')
    .then(model => loadMap('map.glb'))
    .then(map => loadSound('engine.mp3'))
    .then(sound => { /* 完成 */ })
    .catch(err => console.error(err));

// 方式 3：async/await（最现代，看起来像同步代码）
async function init() {
    const model = await loadModel('f18.glb');
    const map = await loadMap('map.glb');
    const sound = await loadSound('engine.mp3');
    // 完成
}
```

本项目使用方式 2 和方式 3 的混合。

## 知识点 2：Promise

### 是什么

`Promise` 是一个「承诺对象」，代表一个未来会完成（或失败）的操作。它有三种状态：
- `pending`：进行中
- `fulfilled`：成功完成，有结果值
- `rejected`：失败，有错误信息

### 最小示例

```typescript
// 创建一个 Promise
function delay(ms: number): Promise<string> {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            resolve('完成了！');  // 成功时调用 resolve
            // reject(new Error('失败了'));  // 失败时调用 reject
        }, ms);
    });
}

// 使用 Promise
delay(1000).then(result => {
    console.log(result);  // 1秒后输出：完成了！
});
```

### 在 F18 项目中的真实用法

```typescript
// 来源：src/vehicleObject/f18/f18Assets.ts
// 把 Babylon 的回调式 API 包装成 Promise
private loadFly(engine, scene: BABYLON.Scene): any {
    return new Promise((success) => {
        // SceneLoader.LoadAssetContainer 是回调式 API
        BABYLON.SceneLoader.LoadAssetContainer(
            url + "assets/mesh/flymesh/",
            "f18_v13.glb",
            scene,
            async (container) => {
                success(container)  // 加载完成，resolve Promise
            }
        );
    })
}
```

这里的关键技巧：**把回调式 API 包装成 Promise**。`LoadAssetContainer` 本来是「加载完了调你的回调函数」，包装后变成「返回一个 Promise，加载完了 resolve 它」。

## 知识点 3：async / await

### 是什么

`async` 标记一个函数为异步函数，函数内部可以用 `await` 等待 Promise 完成。`await` 会暂停当前函数的执行，但不会阻塞整个程序。

### 最小示例

```typescript
// async 函数总是返回 Promise
async function fetchData(): Promise<string> {
    const result = await delay(1000);  // 等待 1 秒
    return result + ' 处理完毕';       // 这个返回值会被包装成 Promise
}

// 调用 async 函数
async function main() {
    const data = await fetchData();
    console.log(data);  // '完成了！ 处理完毕'
}
```

### 在 F18 项目中的真实用法

```typescript
// 来源：src/index.ts —— 整个游戏的启动入口
window.addEventListener('DOMContentLoaded', async () => {
    // 1. 等待 Ammo.js 物理引擎初始化（wasm 编译需要时间）
    await window["Ammo"]()
    
    // 2. 创建游戏实例
    let game = new Game('renderCanvas');
    
    // 3. 等待场景创建完成（包含所有资源加载）
    game.createScene();
});
```

```typescript
// 来源：src/game.ts createScene 方法
async createScene() {
    this.scene = new BABYLON.Scene(this._engine);
    this.scene.enablePhysics(...);

    this._engine.displayLoadingUI();  // 显示加载界面

    // await 等待 F18 模型加载完成，才继续执行
    let f18FighterAssets = new F18Assets(this._engine, this.scene)
    await f18FighterAssets.init()     // ← 这里会等待 glb 文件下载完
    this.flyMesh = f18FighterAssets;

    // await 等待地图加载完成
    this.airportScene = new AirportScene(this.scene, this._engine)
    await this.airportScene.init()    // ← 这里会等待 map.glb 下载完

    // 到这里，所有资源都已加载完毕
    this.flyList[0] = new F18Physics(...)
    this.flyList[0].init(...)

    this._engine.hideLoadingUI();     // 隐藏加载界面
    this._engine.runRenderLoop(() => { this.scene.render(); });
}
```

### 执行顺序可视化

```
DOMContentLoaded 触发
    ↓
await window["Ammo"]()  ← 暂停，等 Ammo wasm 编译
    ↓（Ammo 就绪）
new Game('renderCanvas')
    ↓
game.createScene()
    ↓
await f18FighterAssets.init()  ← 暂停，等 f18_v13.glb 下载
    ↓（模型就绪）
await this.airportScene.init() ← 暂停，等 map.glb 下载
    ↓（地图就绪）
创建飞机实例，启动渲染循环
```

## 知识点 4：Promise.all —— 并行等待

### 是什么

如果多个异步操作互不依赖，可以并行执行，用 `Promise.all` 等待全部完成。

### 最小示例

```typescript
// 串行（慢）：总时间 = 1s + 2s = 3s
const a = await loadA();  // 等 1s
const b = await loadB();  // 等 2s

// 并行（快）：总时间 = max(1s, 2s) = 2s
const [a, b] = await Promise.all([loadA(), loadB()]);
```

### 在 F18 项目中的应用

本项目的 `f18Assets.init()` 里，F18 主模型和爆炸模型是串行加载的：

```typescript
// 来源：src/vehicleObject/f18/f18Assets.ts
public async init() {
    // 串行：先加载主模型，再加载爆炸模型
    this.assetContainer = await this.loadFly(this.engine, this.scene);
    this.assetExplodeContainer = await this.loadFlyExplode(this.engine, this.scene);
    // ...
}
```

> ⚡ 优化机会：这两个加载互不依赖，可以改成并行：
> ```typescript
> [this.assetContainer, this.assetExplodeContainer] = await Promise.all([
>     this.loadFly(this.engine, this.scene),
>     this.loadFlyExplode(this.engine, this.scene)
> ]);
> ```

## 知识点 5：帧循环中的「伪异步」

### 是什么

游戏的渲染循环不是真正的异步，而是每帧调用一次回调。Babylon.js 用 `Observable` 模式实现这个机制。

### 在 F18 项目中的真实用法

```typescript
// 来源：src/vehicleObject/f18/f18Physics.ts
private beforeRender;  // 保存订阅句柄，用于后续取消订阅

private addEvent() {
    // 订阅「每帧渲染前」事件
    this.beforeRender = this.scene.onBeforeRenderObservable.add(() => {
        this.render()  // 每帧调用一次
    })
}

private removeEvent() {
    // 取消订阅（销毁飞机时调用）
    this.scene.onBeforeRenderObservable.remove(this.beforeRender)
}
```

这不是 `async/await`，而是「注册回调，每帧触发」。理解这个模式是理解整个项目运行机制的关键。

### 帧循环 vs 异步加载的区别

```
异步加载（一次性）：
  发起请求 → 等待 → 完成 → 继续

帧循环（持续性）：
  注册回调 → [每帧] → 调用回调 → [每帧] → 调用回调 → ...
  直到 removeEvent() 取消注册
```
